==========================================
Git Commit Message 提交格式模板
==========================================

【格式】
<类型>(<范围>): <简短描述>

<可选的正文，详细说明改动内容>

<可选的脚注，如关联 issue、破坏性变更说明>

------------------------------------------
【类型 type】（必填，从以下选择一项）
  feat      : 新功能（feature）
  fix       : 修复 bug
  docs      : 文档变更
  style     : 代码格式调整（不影响逻辑）
  refactor  : 重构（既不是新增功能，也不是修复 bug）
  perf      : 性能优化
  test      : 增加/修改测试
  build     : 构建系统或外部依赖变更
  ci        : CI 配置变更
  chore     : 其他杂项（不影响源码和测试）
  revert    : 回滚之前的提交

【范围 scope】（可选，说明影响的模块）
  示例：mc_pos_control、logger、uORB、head_pitch_controller 等

【简短描述 subject】（必填）
  - 使用中文或英文均可，保持简洁（建议不超过 50 字符）
  - 不加句号结尾
  - 使用祈使语气（如"添加"而不是"添加了"）

【正文 body】（可选）
  - 说明改动的动机、实现方式、与旧行为的对比
  - 每行建议不超过 72 字符

【脚注 footer】（可选）
  - 关联 issue：Closes #123 / Fixes #456
  - 破坏性变更：BREAKING CHANGE: <说明>

------------------------------------------
【示例】

示例 1（简单修复）：
  fix(mc_pos_control): 修复降落时高度设定值抖动的问题

示例 2（带正文和脚注）：
  feat(head_pitch_controller): 新增云台俯仰角速度前馈补偿

  在位置环输出基础上叠加前馈项，减小跟踪滞后。
  参数 FF_GAIN 可通过 QGC 地面站在线调节。

  Closes #1024

------------------------------------------
【注意】
  1. 一次提交只做一件事，避免混合多个不相关的改动
  2. 提交前确认 git status，不要提交无关文件
  3. 不要提交包含敏感信息的文件（如 .env、密钥等）
